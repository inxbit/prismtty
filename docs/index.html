  • Follows every hop

    One wrapped shell switches profiles as you ssh from device to device, and back again on exit.

  • Nine built-in profiles

    Cisco, Juniper, Fortinet, Palo Alto, Arista, Aruba CX, Versa and Linux, on a generic base.

  • Nothing stored by default

    No network code and no telemetry. Output is never written unless you ask for a trace.

One shell follows every hop.

Start one wrapped shell with ptty /bin/zsh and keep your usual ssh, telnet and console habits. When a login banner or prompt matches after you jump, PrismTTY switches to that vendor's profile. When the connection closes, it switches back.

Nine built-in profiles, written clean-room.

Each profile knows how its platform writes prompts, interfaces, addresses, protocol state, counters and syslog severity. The generic profile underneath covers IPv4, IPv6, MAC addresses and common state words everywhere.

ptty /bin/zsh generic + cisco

Up and highlighting in one line.

macOS and Linux. Homebrew installs prismtty, ptty and ct, shell completions and the PCRE2 dependency. Cargo needs Rust 1.85 or newer, PCRE2 and pkg-config.

Homebrew $ brew install inxbit/tap/prismtty
Cargo $ cargo install prismtty
Run $ ptty /bin/zsh

crates.io GitHub releases Homebrew tap Library docs

Live terminal highlighting, not device management.

What it colors

  • Prompts
  • Interfaces
  • Addresses: IPv4, IPv6, MAC
  • Protocol and operational state
  • Syslog severity
  • Counters and vendor terms

In output that already reaches your terminal. Existing ChromaTerm configs load as they are, and ct keeps the old command name working.

What it never does

  • Log in to devices
  • Collect inventory
  • Push configuration
  • Store operational data
  • Open a network connection

Not an NMS, a configuration tool, a source of truth, a SIEM, a log platform or an inventory system. The binary has no network code.
